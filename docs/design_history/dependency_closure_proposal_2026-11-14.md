# Dependency-aware compilation and validation

Status: design proposal, not permission to reuse an object or a test result.
Baseline: `dev` at `2e3aa910`. The November 14 implementation first makes
validation units smaller; it deliberately leaves dependency-based reuse unchanged.

## One graph, two identities

The graph describes the inputs to a generated entry point, not just the Python
file containing its emitter. Nodes include emitted functions and constants,
model data, feature and resource configuration, included helpers, translation
units, tests, fixtures, reference implementations and acceptance policy.
Edges must record their provenance: explicit declaration, parsed generated-code
reference, compiler dependency output, or conservative whole-family fallback.

An **object identity** covers the transitive compiled source/header bytes,
defines, compiler and host compiler identities, flags, architecture, ABI,
generator configuration and dependency-detector schema. A **test-evidence
identity** additionally covers the exact node IDs, fixtures and inputs, reference
code, tolerances, skip policy and verification policy. Equality of object keys
does not imply equality of evidence keys. Signed evidence must still satisfy
the existing ancestry, age, signer, scope and carry rules.

The existing consumer store in `bindings/grid_rbd/_artifacts.py` already records
toolchain, generated-header, source, dependency and configuration identities.
Extend its audited dependency machinery rather than introduce a second cache
with different invalidation rules. The split driver's codegen-neutrality proof
also explicitly treats reference changes separately; preserve that distinction.

## Conservative resolution

Start from generated bytes and explicit exported-entry metadata. Follow calls,
types, constants and layouts, including their transitive dependencies. A textual
search alone cannot reliably resolve templates, macros, overloads, conditional
compilation or indirect dispatch. Until a construct is covered, associate its
whole generated family or translation unit with the entry point. Unknown
generator configuration invalidates the whole relevant domain. A changed shared
fixture or oracle invalidates every test using it even if codegen is byte-identical.

Model identity must include inertial values, topology, joint semantics, coupling,
armature, base mode and enabled outputs—not merely dimensions or a URDF filename.
Header layout, workspace offsets and wrapper ABI are dependency nodes. New or
deleted tests require recollection; they cannot inherit an old manifest silently.

The graph report should explain every decision: changed node, affected exports,
affected compile atoms, affected tests, unresolved edges and fallback boundary.
An unknown edge is a reason to widen, never to declare something unaffected.

## Report-only experiment

Run the detector without altering keys, skipping builds or carrying receipts.
Use small deterministic generation fixtures and deliberately mutate:

- one leaf emitter; a shared spatial helper; a template and a feature macro;
- a model inertia and a topology/coupling option with unchanged dimensions;
- a wrapper signature, workspace layout, compiler define and compiler identity;
- an oracle, tolerance, test input, shared fixture and expected-skip policy;
- an unrelated documentation paragraph and an unrelated algorithm family;
- an unresolved include/dispatch path and a new test node.

Compare predictions with independent whole-header regeneration, compiler
dependency lists where available, and the full test dependency inventory. CPU
checks can establish graph consistency and broad fallbacks. Actual compilation
and correctness comparisons need a separately approved GPU window. Record both
false invalidations and missed dependencies; no missed dependency is acceptable
in the designed mutation suite. Keep broad invalidation on any detector failure.

Only after review should object reuse be narrowed. Evidence reuse is a second,
separate rollout with adversarial oracle/policy/fixture mutations and the existing
full-scope gate. Keep a force-broad mode and a schema bump that invalidates all
old narrowed keys. Report-only measurements, not an assumed percentage gain,
decide whether decentralizing registration or splitting helpers is worthwhile.

## Next work package

Implement the graph schema, explicit export metadata for one inverse-dynamics
family, mutation fixtures and an explanation-only CLI. Do not change public
registration, cache semantics or receipt acceptance in that package. Its exit
deliverable is a coverage/unknown-edge report and a costed proposal for the next
family. Broad registration refactoring remains deferred.
